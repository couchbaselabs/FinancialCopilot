FinBase. — Architecture

Wealth Management Advisor Copilot · Couchbase Capella + local LM Studio (BERT embeddings + Gemma)

System overview

FinBase is a three-tier app with a local inference sidecar. A static single-page frontend calls an Express API, which reads/writes a single Couchbase Capella bucket and calls LM Studio for embeddings and generation. Every AI feature degrades gracefully to a heuristic when LM Studio is unavailable.

Data model

One Capella bucket (portfolio), documents discriminated by a type field and keyed by convention. Copilot holdings carry a client_id; legacy holdings do not, which keeps the two datasets isolated in the same bucket.

Ask flow (cache → retrieval → generation)

  1. Embed the question with bge-m3 (BERT).
  2. Cosine-compare against cached question embeddings. If max ≥ 0.75 → cache HIT: return the cached answer, bump hit_count, record the new phrasing.
  3. On a miss, retrieve the top-3 research notes by embedding similarity, add optional client context (profile + memory facts).
  4. Prompt gemma-4-e4b to answer in 2–4 sentences, grounded in that context.
  5. Write-through: store the generated Q/A as a new semantic_cache_entry so future repeats become cache hits.
If LM Studio is unreachable, steps 1–5 fall back to Jaccard token-overlap matching and a canned "ask your advisor" response — the app never hard-fails.

Run

npm run dev starts the API (:3001) and static frontend (:3000) together. Data: npm run seed:copilot. Inference: load text-embedding-bge-m3-embeddings and google/gemma-4-e4b in LM Studio (lms load …), listening on :1234.
